# 08 — 12 週學習與交付計畫（建議）

以每週數小時的方式安排，**以階段驗收取代硬性進度**。程式練習放在這個學習 repo；正式交易分析程式日後可獨立放入 `QuantitativeTrading` repo。

| 週次 | 學習重點 | 交付 | 自我驗收 |
|---|---|---|---|
| 1 | Git、Python、資料結構與 CSV | 本地環境與第一個測試 | 能執行 [Lab 1](07-first-running-lab.md) |
| 2 | 台股交易流程、OHLCV、交易日曆 | 基本資料字典 | 能辨認交易日和資料發布日 |
| 3 | 報酬、CAGR、波動率、MDD、Sharpe | 自製小型績效計算器 | 可手算幾筆數據比對 |
| 4 | MA、RSI、Momentum 與 warm-up | 指標函式及測試 | 避免使用未來收盤價 |
| 5 | 資料清理、復權、股利、股票池 | OHLCV 資料驗證器 | 能偵測重複／缺漏／異常 |
| 6 | 回測事件順序、資金帳與成交 | T+1 回測進階練習 | 訊號時間、成交時間可稽核 |
| 7 | 交易成本與 Benchmark | 成本敏感度與基準比較 | 知道何時勝過基準 |
| 8 | 動能、趨勢、均值回歸 | 兩種策略研究規格 | 策略規則無歧義 |
| 9 | OOS、Walk-forward、參數敏感度 | 策略穩健性報告 | 能指出失效或過度擬合 |
| 10 | 股票池、部位配置與風控 | Target positions + 風控 | 無資料或禁買時不出交易建議 |
| 11 | 排程、資料快照、冪等與日報 | 每日分析 MVP 原型 | 可重跑且保留不同資料修訂版本 |
| 12 | 紙上交易、覆核、失敗演練 | 完整實驗報告與交接說明 | 能人工核對訊號與風險 |

## 每一週固定四件事

1. **Understand**：用自己的文字描述定義、假設與風險。
2. **Build**：完成一個短小、可重跑的程式或可驗證公式。
3. **Test**：正常情況、缺漏資料、時間邊界至少各一例。
4. **Review**：記錄成功和失敗案例，保留 Git commit 與實驗參數。

## 三個必須過的關卡

**Gate A — Data Correctness**（第 5 週）：有可重現的行情、時間戳、股票池；不能使用事後才知道的資料。

**Gate B — Strategy Integrity**（第 9 週）：基準、交易成本、樣本外與合理參數變動後的結果完整；允許淘汰效果不佳的策略。

**Gate C — Daily Operation**（第 12 週）：交易日判斷、資料完整性、訊號與風控分離、失敗關閉、保留每次修訂、人工覆核；零自動下單。

## 研究紀錄規則

- 每項練習可開一個 GitHub Issue，放學習目標與驗收條件；在 PR 附上測試結果及失敗案例。
- 研究成果不可只寫「勝率高」；要註明區間、資料版本、樣本外結果、成本與未解限制。
- 同一策略不需要永遠變複雜；如果簡單模型未通過 Gate B，就先改善資料或檢查假設。
