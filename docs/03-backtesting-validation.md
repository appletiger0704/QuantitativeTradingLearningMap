# 03 — 回測與策略驗證

## 正確的日線事件順序
```text
T 日收盤行情可取得
    → 完成資料檢核 → 計算 T 日特徵 → 產生 T 日收盤後訊號
    → T+1（下一個可交易時點）嘗試成交
    → 扣除成本、更新現金／持倉 → 計算投組市值
```
不得以 T 日收盤後才知道的訊號，假設用 T 日收盤成交。T+1 開盤也非保證成交，須考慮缺量、跳空、漲跌停、暫停交易與部分成交。

## 必備回測元素
- 初始資金、可交易股票池、現金、持倉、訊號到下單的延遲。
- 手續費、交易稅（依實際標的與交易方式適用規定）、買賣價差、滑價、最低費用；**不要硬編永久費率**。
- 整股／零股約束、流動性與單日參與率、買賣執行順序、持倉上限。
- 與持續持有基準（例如 0050 含息總報酬版本）比較；明確紀錄交易所指數是否含息。
- 把股利、公司行動、停止交易與下市退場規則納入會計。
- 保存交易明細、逐日投組值、成本及無法成交原因。

## 常見偏誤與預防
| 風險 | 問題 | 檢查 |
|---|---|---|
| Look-ahead | 使用未來資料 | as-of 截斷、T+1 撮合 |
| Survivorship | 僅保留現存股票 | 歷史成分與下市樣本 |
| Data snooping | 大量試驗只報最好者 | 保存所有實驗／候選 |
| Overfitting | 策略只適合過去區段 | 保留 OOS、走期測試 |
| Execution optimism | 假設總能理想成交 | 滑價、限量、漲跌停壓力 |
| Revision bias | 使用事後修訂財報 | point-in-time 發布版本 |

## 驗證程序
1. 時間分割：先選研究期（in-sample）與未碰過的驗證期（out-of-sample），不任意反覆調整驗證期。
2. Walk-forward：多個連續訓練／驗證區間，**只用過去參數預測下一段**。
3. 穩健性：不同期間、類股、股票池與合理參數小範圍變動。
4. 成本壓力：費用與滑價提高後是否依然合理；資金容量是否足夠。
5. Benchmark：比較 CAGR、MDD、Sharpe、Turnover 與風險調整績效。
6. 判定：若無樣本外優勢、對單一參數極度敏感或成本後表現不佳，標記「淘汰／待研究」，不得只選漂亮圖表。

## 回測測試案例
- 無價格資料時不得成交。
- 零訊號、全現金時淨值應維持不變（忽略利息）。
- 買賣費用應降低淨值，持倉與現金不得無故為負。
- 同一份資料與相同版本／設定重跑應有相同結果。
- Signal timestamp 應早於模擬 Fill timestamp。
